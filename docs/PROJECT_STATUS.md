## Active execution slice

**Roadmap alignment:** Phase 6 — AI employee customer boundary.

**In scope:** Replace the preview workspace with durable customer-scoped reads and atomic decisions, harden migration `072`, and add authorization/idempotency coverage without applying hosted schema or creating customer data.

**Current implementation:** The protected workspace now loads customer membership, employee configuration, schedules, capped queue records, immutable activity, outcomes, and guardrails through user-scoped Supabase reads. Decisions use one atomic database function to verify membership, enforce one decision per item, reuse idempotent retries, and update work status. Migration `072` remains local and unapplied pending behavioral RLS review.

**Before review:** Run `git diff --check`, targeted unit/API and authorization tests, and the relevant retained-route smoke checks. Run `npm run type-check` and `npm run build` when application code changes. Record any unavailable integration checks below.

**Rollback:** Revert the focused implementation commit. Do not pair an irreversible schema change with a broad removal.

**Blockers:** Migration `072` must pass local behavioral RLS and function tests before hosted review. Until it is deployed and NeedThisDone is provisioned, authenticated users see a truthful setup or unlinked state rather than sample customer work.

**Deferred work:** Stripe test Payment Link creation and checkout verification remain undone by owner decision. Resume only when the owner chooses to obtain a Stripe-issued test secret key. Until then, public offering actions continue to use the project-request fallback; this does not block removal of the empty legacy commerce application.

**No-broken-windows policy:** Every warning, failing check, stale route or document, broken interaction, and unresolved TODO is a defect. Fix it in the current slice, or record an owner-approved exception here with scope and removal date. An open exception blocks production promotion.
